# AuthorHub — shared agent entry point

## Product and evidence

- Read `README.md`, `PROJECT_CHECKLIST.md`, and `PROGRESS.md`; inspect applicable scoped guidance. The baseline is documentation-first: README's planned stack and linked specifications are not implemented capabilities.
- Preserve the source-grounded nonfiction starting scope and genre-neutral canonical manuscript model. Do not expand the first release into every genre or publishing workflow.
- Keep sources, claims/citations, manuscript revisions, editorial decisions, and exports traceable. AI may assist, not become the factual source or silently replace author decisions.
- Manuscripts and sources are user intellectual property. Require tenant isolation, explicit AI data-use boundaries, reproducible exports, backup/recovery, and deletion controls before public release; use synthetic or rights-cleared fixtures.
- Start with one valuable end-to-end journey and explicit non-goals, such as saving a structured draft with a traceable source reference, reloading it, and proving another user cannot retrieve it. Future exports must come from the canonical manuscript, not diverging copies.
- Treat the README's Next.js/Supabase/editor/retrieval/jobs architecture as planned context. Introduce components only when the selected milestone needs them; do not provision every planned service at once.
- Current owner instructions and approved controls govern authority. Retain any adopted `APP_PROJECT_CONTROL_STANDARD.md` as canonical; link detailed specifications when they actually exist, not another constitution.

- Load product/architecture/security/AI/export references only as relevant. Create populated documents when decisions exist rather than empty folders or duplicate manuals.

## Economical CI and delivery

- Run focused local checks before coherent pushes; broaden for data/permissions, shared contracts, dependency/toolchain/workflow, and agent-policy changes. Diagnose full failing logs before reruns.
- Avoid speculative pushes, duplicate expensive jobs, repeated matrices, and unrelated hosted work. Ordinary prose-only routing needs an explicit allowlist; agent/release policies and executable Markdown require relevant validation.
- Keep required workflows observable; test routing and an always-evaluated final gate rejecting failed/cancelled/missing required work. Cancel superseded PR validation only where safe, not blindly deployments/migrations.
- Use least privilege, immutable action references, and untrusted/privileged separation. Verify actual platform rules, project IDs, environment scopes, deployment triggers, recovery, and release authorization before merging; merging may deploy.
- Reuse approved infrastructure and previews. Fix relevant blockers/invariant violations; record unrelated cleanup without expanding the release milestone.

## Handoff

- Track implemented, wired, locally verified, hosted verified, and released independently with exact SHA, command/results, environment, and evidence. Mock AI, planned specs, and source files are not hosted integration proof.
- Keep the checklist evidence-linked and progress handoff concise; preserve history when archiving. Report actual checks, blockers, genuine owner decisions, and next smallest task.
- Use skills selectively, one implementer plus separate review by default. Confirm fresh Codex/Claude instruction loading and actual command discovery.
